# 运行与部署

## 本地运行

需要 Node.js 22.13+ 或 24+、Python 3.11+。核心 HTTP 服务不需要安装第三方 Python 依赖。

```sh
npm ci
npm run build
python scripts/start.py
```

地址是 `http://127.0.0.1:8787`，默认监听本机。数据在 `server/storage/`；用 `SEDIMENT_STORAGE` 指定其他目录，用 `SEDIMENT_PORT` 修改端口。公开代码从空知识空间开始，不加载原有用户资料。

本地首次运行没有登录页。在「偏好设置 → 账号与空间」启用账号后，当前内容归属该账号，关闭匿名访问；之后的新账号拥有独立空间。不要在共享设备上保留明文账密、Key 或账号保存卡。

开发预览：一个终端运行 `python server/app.py`，另一个运行 `npm run dev`。Vite 监听 5173，系统 API 转给默认的 8787 后端；改变后端端口时同步调整 `vite.config.ts`。AI 始终由浏览器直连，不使用系统代理。

完成构建后，也可使用 `bash start.sh`、`启动.cmd` 或 `启动.command`。浏览器检查及已知环境限制见 [验证记录](验证记录.md) 和 [插件开发与验收](浏览器插件开发与验收.md)。

## 生产模式

先构建前端，将 `dist/`、`server/` 与对应项目源码部署到同一根目录。服务账号需要读构建文件、写自己的存储目录；不能用空存储覆盖已有实例。

下面是新实例的配置示例，地址、路径和所有者标识换成自己的：

```sh
export SEDIMENT_STORAGE=/srv/sediment/storage
export SEDIMENT_PUBLIC_URL=https://knowledge.example.com
export SEDIMENT_OWNER=owner-your-instance
export SEDIMENT_PORT=8787
export PYTHONUTF8=1
```

在开放公网前离线创建所有者，始终使用同一份 `SEDIMENT_STORAGE` 和 `SEDIMENT_OWNER`：

```sh
python scripts/provision-owner.py --email owner@example.com --name 所有者
```

脚本交互读取至少 12 字符的密码，不回显。也支持 `--password-file`；使用密码文件时限制权限，配置完成后妥善处理，不能提交仓库。

随后启用生产模式并启动：

```sh
export SEDIMENT_ENV=production
python server/app.py
```

生产地址必须是有效 HTTPS origin，不带路径、查询或凭据。所有者必须已存在且未停用，否则服务拒绝启动。不会让首次访问者认领实例。

服务仍监听 loopback，由 Nginx 等反向代理提供 HTTPS。代理保留公开域名，浏览器请求的 Origin 必须与 `SEDIMENT_PUBLIC_URL` 一致。用自己的服务管理器守护项目，别把前台终端当作长期守护进程。

- `/api/health` 可匿名读取，只表示服务健康，不代表所有业务已验收。
- `/api/state` 在生产模式下要求登录，匿名返回 401。
- 公开运营自行配置认证限流、配额、监控和备份。当前没有邮件验证或找回密码。
- 不公开存储目录、数据库、环境文件和私有导入包。边缘缓存不能替代账号鉴权。

## 更新与迁移

更新前停止项目服务，冷备完整存储目录与旧前端，记录回滚版本。发布新前端时保留旧哈希资源，避免已打开的页面找不到文件；启动后进行最小健康、鉴权与版本读回。测试套件在隔离环境运行，不在生产库创建测试账号或内容。

整实例迁移先停服务，再复制完整存储目录，避免漏掉 SQLite WAL；也可通过 `SEDIMENT_STORAGE` 使用迁移后的目录。恢复前保留当前数据。个人备份按用户隔离，AI 地址、Key 和模型配置不随知识备份迁移。

外部种子只供空实例首次初始化：启动前设置 `SEDIMENT_SEED_DIR` 指向仓库外目录，包含 `ks_items.json`、`ks_replies.json`、`ks_profiles.json`。初始化只执行一次，真实种子和迁移包不能加入 Git。

## SDK、CLI 和 MCP 是另外一层

先在系统「连接与迁移」创建范围授权，再安装客户端：

```sh
python -m pip install -e ".[mcp,keychain]"
sediment keychain-set my-agent
sediment profile-add default --url http://127.0.0.1:8787 --credential keychain:my-agent
sediment capabilities
sediment mcp
```

`keychain-set` 交互将令牌放进系统钥匙串。钥匙串不可用时，使用 `--credential env:SEDIMENT_TOKEN`，由运行环境提供变量；配置文件不接受明文令牌。

远程 MCP 是独立进程，不是核心站点自动提供的端点：

```sh
sediment mcp --transport streamable-http --url http://127.0.0.1:8787 --resource http://127.0.0.1:8791/mcp --port 8791
```

资源地址必须与核心的 `SEDIMENT_MCP_PUBLIC_URL` 完全一致。公开远程资源需要独立 HTTPS 反代，并核对授权发现、受众和 PKCE；首页可访问不代表远程 MCP 可用。

协议、目标平台和授权细节见 [开放知识与连接器](开放知识与连接器.md)。
