# 沉淀浏览器插件开发与验收

插件源码位于 extension，目标为可本地安装的 Edge 和 Chrome MV3 版本。系统既有 API 已能提供范围读取、直接创建笔记和提案，所以本次没有修改后端。唯一共享业务修改是 AI 客户端增加显式本机无 Key 模式，默认认证行为不变。

## 模块职责

| 模块 | 职责与扩展方法 |
| --- | --- |
| extension/src/types.ts | 版本化捕获包、队列、授权和 AI 配置契约。 |
| extension/src/capture/extract.ts | 惰性注入，解析惰性文档副本；通用提取与 SiteAdapter 注册表。新增站点先补合成 DOM 测试，不混入提交逻辑。 |
| extension/src/core/capture.ts | 严格输入投影、URL 规范化、已知凭据脱敏、组合兼容系统的笔记正文。 |
| extension/src/core/queue.ts | 可注入存储、发送与时钟的队列状态机，与 Chrome 解耦。 |
| extension/src/core/oauth.ts | 公共客户端注册、PKCE、回调验证、令牌交换与撤销。 |
| extension/src/core/ai.ts | 四种任务与分段调用规划，不包含系统写入权限。 |
| extension/src/platform | Chrome 存储、主机授权、账号绑定与内部消息边界。 |
| extension/src/background.ts | 手势采集、逐窗口暂存、持久队列与受限消息路由。每次 worker 冷启动恢复未确认任务。 |
| extension/src/panel | React 界面，复用品牌；展示真实状态，不自行绕过后台提交。 |
| extension/src/sdk.ts | 无 Chrome 依赖的程序入口，构建 ESM SDK 与 TypeScript 声明。 |
| extension/capture.schema.json | 给其他语言程序使用的捕获包 schema；运行时仍检查 URL 凭据、长度和业务约束。 |

## 构建与检查

仓库根目录运行：

```powershell
npm.cmd ci
npm.cmd run typecheck:extension
npm.cmd run test:extension
npm.cmd run build:extension
npm.cmd run test:browser:extension
```

构建生成 build/browser-extension/unpacked、ZIP 和 artifact.json 的 SHA256。只允许删除带标记的构建目录下自己的 unpacked，不覆盖其他用户目录。只从白名单复制扩展文件、schema、SDK、图标和依赖许可证，绝不压缩整个仓库、数据库、导入档案、浏览器资料或凭据。发布包没有 source map、远程脚本或动态 eval。

集成脚本需要 Playwright 和支持加载扩展的 Chromium。默认可使用本机 Codex bundled Playwright；其他开发环境可自行安装 Playwright，并设置 CHROMIUM_EXECUTABLE、PYTHON，必要时设置 CODEX_NODE_MODULES。不要指向日常使用的浏览器资料目录。自动创建新 profile、独立 SEDIMENT_STORAGE 与随机本机端口，结束即关闭测试进程。

## 程序调用示例

Node 22 及以上可以使用安装包 SDK。程序自己的范围授权放环境变量，不把真实令牌写进脚本或捕获包。

```javascript
import {
  freshCapture, validateCapture, composeWrite, CaptureClient
} from './sdk/capture.mjs';
import { writeFile } from 'node:fs/promises';

const capture = freshCapture('thought', '今天形成的一个新理解。');
// 路线一：导入插件草稿页，再由用户确认上传。
await writeFile('capture.json', JSON.stringify(validateCapture(capture)));

// 路线二：外部程序使用自己的范围授权，直接调用系统。
const client = new CaptureClient(
  process.env.SEDIMENT_ORIGIN,
  process.env.SEDIMENT_TOKEN
);
const capability = await client.capabilities();
if (!capability.scopes.includes('knowledge:write')) {
  throw new Error('This program requires explicit write permission');
}
const result = await client.write(composeWrite(capture), 'clip-v1:' + capture.id);
if (!result.item_id) throw new Error('Write was not confirmed');
console.log(result.item_id);
```

重试必须使用相同授权、同一 capture.id、完全相同 payload 与 Idempotency-Key。不要每次网络异常都调用 freshCapture。SDK 不替外部程序建立持久队列；需要可靠重试时，程序自行保留捕获包和提交状态，或经插件草稿确认提交。capture.schema.json 不是授予写权限的机制。

## 队列与错误处理

pending 先落盘，sending 代表等待确认，收到 item_id 后才 saved；proposals 返回提案 ID 时为 proposal，绝不是已沉淀。400、401、403、404、409、413 停止自动发送；网络、429 和其他临时错误按退避重试，最多五次，每次唤醒串行处理最多三条。

worker 冷启动将 sending 恢复为 pending，保留提交身份。账号、origin 或 grant ID 不匹配就不发送。刷新响应晚于账号切换时，不能覆盖或清除新账号授权。本机移出未知结果任务之前明确提醒可能已写入，先核对系统，不能把本机删除当作服务端回滚。

队列保留最近二十条已确认记录，最多五十条待处理；队列与草稿分别设预算，并处理存储失败。没有 unlimitedStorage，超限不是默默丢弃。账号和设备草稿都可导出捕获包。导入作为新稿，拒绝未知字段、秘密配置与可执行动作，绝不自动上传。

## 仍需真实安装验收

自动测试使用独立测试副本，只预授予本机 127.0.0.1 主机，便于隔离集成。原始发布 manifest 没有 host_permissions，保留 optional_host_permissions。不能把这个替代过程称为真实权限弹窗验收。

真实 Edge 和 Chrome 中还需检查：工具栏原生侧栏打开、快捷键冲突、右键入口与 activeTab 权限生命周期、首次服务主机权限批准、交互 OAuth 窗口，以及用户实际 AI 服务的鉴权与模型权限。系统 OAuth 和共享 AI 协议已分别有本地检查，但不冒充这些浏览器与外部服务验收。

真实 X/Reddit DOM 会变、登录态和可加载内容不同，合成适配测试不能保证每个真实页面完整提取。失败须诚实降级，不为通过验收使用整页 innerText 混入表单或导航。图片、PDF、截图 OCR、完整线程与浏览器商店发布均未交付。

## 本次变更边界

没有上线服务器、修改 Cloudflare、写入任何真实账号，也没有在服务器跑测试。保留仓库已有 App.tsx 与 Reading 到 ReadingView 的未提交改动；新增插件修改不回退它们。安装动作仍由用户在浏览器扩展管理页完成，ZIP 不是可以静默安装的程序。
