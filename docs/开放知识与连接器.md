# 开放知识与本地连接器 · v4.3

本版本实现 API、CLI、Python SDK、本地与远程 MCP、OAuth、四个 Agent Skill、范围授权、待采纳建议、源修订、精确知识包、审批、租约任务、增量规则、团队治理和三个本地连接器。本次更新代码，没有上线服务器，也没有把原有用户与帖子提交到仓库。

## 三类凭证

| 凭证 | 保存位置 | 用途 |
| --- | --- | --- |
| 自己的 OpenAI / Anthropic API Key | 按账号隔离的浏览器 localStorage／sessionStorage | 浏览器直接调用模型；不会经过沉淀服务、MCP或数据库 |
| 沉淀访问令牌 | 自己的系统钥匙串或环境变量；核心服务只保存哈希 | 让自己的 Agent／连接器访问明确范围 |
| 飞书 / ima 凭证 | 本地连接器的环境变量或系统钥匙串引用 | 本地进程直接调用目的地；不提交到沉淀数据库 |

目的地页面只保存路径、目标 ID 与凭证引用到本浏览器；下载的 JSON 配置没有明文 Key。连接器账本保存任务、短时租约与外部对象映射，权限为当前操作系统用户可读写。

## 授权一个 Agent

1. 打开“偏好设置 → 连接与迁移 → Agent 授权”。
2. 选择空间、主题或精确条目，可排除记录；不选择“未来新增”时，捕获本次已有条目清单。
3. 勾选可读层次。历史和附件需要对应的独立权限；个人回顾状态不进入 Agent 投影。
4. 默认只读。建议、外部沉淀、执行、增量、直接写入分别授权；后者只支持新增记录和补充，受每日上限限制。
5. 令牌仅显示一次。放入系统钥匙串或环境变量。有效期为 7／30／90 天，可轮换或撤销。

第三方得到明文后能够保存副本。禁止“生成导出计划”不是可靠的复制防护；不希望第三方取得正文时，应禁止其读取。撤销阻断后续访问，无法收回已有副本。

团队知识默认禁止外部读取及外发。管理员在团队策略中开启范围和目标平台；服务账号必须显式加入团队，不拥有个人知识或平台管理员能力。启用个人登录后才能创建服务账号，避免本地无账号实例被机器账号锁住。

## Python SDK 与 CLI

在项目目录安装：

```sh
python -m pip install -e ".[mcp,keychain]"
sediment keychain-set research-agent
sediment profile-add default --url http://127.0.0.1:8787 --credential keychain:research-agent
sediment capabilities
sediment search '关键词' --space personal --fields original,current_understanding
sediment read ITEM_ID --revision 3 --parts SEGMENT_ID --fields original
sediment changes
```

系统钥匙串不可用时，指定 `--credential env:SEDIMENT_TOKEN`，由本机运行环境提供变量。命令行不接收明文令牌，配置文件只存引用；不会自动降级为明文文件。多个实例可用不同 profile：`sediment --profile NAME capabilities`。

```python
import os
from sediment import Client

client = Client("http://127.0.0.1:8787", os.environ["SEDIMENT_TOKEN"])
results = client.search("关键词", space_id="personal", fields=["original"])
package = client.extract(
    [{"item_id": "ITEM_ID", "revision": 3, "part_ids": ["SEGMENT_ID"]}],
    fields=["original"], purpose="portable_export", max_characters=20000,
)
```

远程地址要求 HTTPS；本机 loopback 可用 HTTP。客户端拒绝重定向，不把授权头转交给另一个地址。SDK只访问当前实例的 `/api/v1`，不读取数据库。

`extract`、`propose`、`prepare-export`、`write` 接受 JSON 文件或 `-` 从标准输入读取。修改前读取修订；重试同一内容使用相同 `--idempotency-key`，内容改变后换一个标识。不要在不明确写入结果时盲目重复。

## MCP 与 Skill

本地：`sediment mcp`，使用当前 source profile，stdout 为 MCP 协议。

```json
{
  "mcpServers": {
    "sediment": {
      "command": "sediment",
      "args": ["--profile", "default", "mcp"]
    }
  }
}
```

远程：独立运行 `sediment mcp --transport streamable-http --url CORE_URL --resource MCP_URL --port 8791`。`MCP_URL` 必须与核心的 `SEDIMENT_MCP_PUBLIC_URL` 完全一致。默认两端均为本机地址；公开域名需要 HTTPS 反向代理，当前没有部署。

保护资源元数据位于 MCP 进程的 `/.well-known/oauth-protected-resource/mcp`；授权服务元数据位于核心服务的 `/.well-known/oauth-authorization-server`。资源路径变化时，元数据路径随 SDK 改变。

OAuth 使用公开客户端、授权码、S256 PKCE、精确预登记回调（HTTPS或loopback）、resource 参数、一次性授权码、1小时以内访问令牌、轮换刷新令牌和根授权撤销。`/oauth/register` 提供有限的动态注册兼容；当前不实现 Client ID Metadata Documents。用户在网页同意具体范围，Agent 无法调用 consent、adopt、approve 等交互控制。

工具：`knowledge_capabilities`、`knowledge_search`、`knowledge_read`、`knowledge_extract`、`knowledge_changes`、`knowledge_propose`、`knowledge_prepare_export`、`knowledge_operation`、`knowledge_write`。名称采用客户端普遍接受的下划线。资源模板 `sediment://knowledge/{item_id}`；资源与工具共享同一授权。

MCP使用官方 Python SDK 1.29.0并由客户端协商协议版本；验证的是该SDK的stdio和Streamable HTTP链路，不宣称支持所有现有客户端或未来协议版本。

`skills/` 的四个标准 SKILL.md 分别提供找回知识、主题沉淀、整理到知识库、新发现写回流程。技能只说明调用顺序，不扩大权限，不包含密钥，也不把知识原文中的指令当作操作授权。

## 提取、整理与待采纳

知识详情、知识集合支持“提取与沉淀”，最多100条；原文、理解、讨论、经验、验证、来源、历史、附件分别选择。预览包含稳定片段、作者、修订及材料覆盖状态，可以进一步精确选择引用片段。

知识包为确定性投影，不调用服务器模型。相同材料的内容哈希可复验；随机 snapshot ID仅标识一次提取。历史引用保留真实旧修订；来源头修订单独绑定审批，允许有意导出旧材料，同时检测准备后发生的修改。

完整记录保留材料；整理成文允许人工编辑，或使用自己的浏览器模型整理。单次稿件整理支持2.4万字材料；更多材料可在既有AI助手中明确允许分段处理。配置Key不作为模型上下文，流式结果及收录前均隐藏已配置凭据。引用索引由连接器根据确认包附带，内部链接仍需源空间访问权限。

Agent提出的建议进入收件箱待采纳区。用户核对来源、编辑后采纳或拒绝；当前理解仅能由原文作者采纳。新的经验默认为待验证；支持、反例和不确定判断需要用户记录条件、观察或证据片段。

## 配置目的地

在目的地页面添加配置，下载JSON，在本机运行：

```sh
sediment connector configure LOCAL_NAME profile.json
sediment connector probe LOCAL_NAME
```

审批中的 target_id 必须与本地配置一致。下面均为非秘密模板，请填入自己的目标 ID 和本地路径，不要提交真实配置到仓库。

### Obsidian

```json
{"kind":"obsidian","target_id":"my-vault","vault":"/ABSOLUTE/PATH/TO/VAULT","folder":"沉淀"}
```

只写所选vault内的普通子目录，拒绝路径穿越与符号链接。笔记带YAML properties、源ID／修订、引用和前一版映射；授权附件保存到相对路径。新文件独占创建、原子写入；更新托管笔记需显式许可，且实际文件哈希必须与上次一致。外部编辑产生冲突，不会静默覆盖。

### 飞书

```json
{"kind":"feishu","target_id":"team-docs","app_id":"YOUR_APP_ID","app_secret":"env:FEISHU_APP_SECRET","folder_token":"YOUR_FOLDER_TOKEN"}
```

知识库目标用 `wiki_space` 与可选 `parent_node` 替换 folder_token；同时配置时优先知识库。也可在本地配置 `user_token:"env:FEISHU_USER_TOKEN"` 替代应用凭证。

探测检查目标读取能力；实际写入还要求应用／用户、云文档、文件夹或Wiki父节点的相应权限。文档创建与知识库节点创建分别处理，正文分块写入并回读。为保存原文，Markdown以文本块保存；不支持覆盖、删除或附件原件上传，后续变化创建新版本并附前一版标识。

### ima

```json
{"kind":"ima","target_id":"my-ima","client_id":"YOUR_OPENAPI_CLIENT_ID","api_key":"env:IMA_API_KEY","mode":"note"}
```

`mode=note` 创建个人笔记，可选folder_id；`kb_note` 增加knowledge_base_id，先创建笔记再加入知识库；`kb_file` 将Markdown走create_media → COS PUT → add_knowledge。使用正式Client ID／API Key，不使用浏览器Cookie。

临时COS凭证仅用于本地上传，验证官方目标域名、对象路径与有效期，不传回核心。知识库入库未确认时，即使笔记／文件已经创建，也不会报告整体成功。不承诺覆盖、删除或附件原件上传。文件回读依赖API提供可用原文地址；不可用时显示待核对。

## 执行、结果不明与冲突

```sh
sediment connector run --plan PLAN_ID --destination LOCAL_NAME
sediment operation PLAN_ID
sediment connector reconcile --plan PLAN_ID --destination LOCAL_NAME
sediment connector watch --once
sediment connector watch
```

source profile 需有 `knowledge:export` 与 `exports:run`；没有本地配置的任务保持排队。一次只有一个本地执行者，核心用10分钟租约与30秒心跳防止重复认领，SQLite保存审批、状态和回执；本地账本持久化写前检查点及返回的目标ID。

无法判断外部写入结果时标为unknown_result，租约到期也进入此状态。不会自动重建。已有目标ID时可用reconcile回读；缺少已确认目标或知识库入库ID时，需要用户在目的地核对，不能宣称自动恢复或跨平台exactly-once。

Obsidian外部编辑冲突会记录为计划阶段失败。可以保留外部文件，重新生成“仅创建新版本”的计划；需要合并时先读取外部修改、人工编辑新稿，再确认新的计划。当前不提供自动覆盖冲突文件。

回执是`runner_reported`，即本地连接器报告。核心不持有外部凭证，不能独立验证。read_back_verified表示连接器确实回读比对；observed_content_sha256计算目标实际文本，可能因托管属性或引用索引与审批正文哈希不同。排队、已创建但未入库、部分成功、未知、取消均不伪称已完成。

固定增量规则仅生成已授权范围的完整记录，绑定字段、目标与每日上限。只在本地watch运行期间写往目的地；核心后台及jobs请求可生成待执行队列。用户可暂停规则，撤销授权后任务无法继续。删除／移出范围只发此前已知ID的移出标记，不自动删除外部副本。

外部修改写回：

```sh
sediment connector pull --plan PLAN_ID --destination LOCAL_NAME
```

使用本地账本找回外部对象，读取当前源修订，再提交待采纳补充；不会直接合并进原文。

## 验证范围与部署

已验证：隔离的合成数据、真实HTTP核心服务、官方MCP SDK实际传输、模拟飞书与ima协议服务、实际本地文件写入与回读，以及浏览器完整流程。没有真实飞书／ima账号凭证，因此没有进行真实账号创建或上传，也没有消耗真实云模型配额。

更新旧实例前备份完整存储目录；首次启动会自动建立修订投影，旧版缺少补充快照的历史明确标注。JSON备份包含不可变修订；导入不会覆盖冲突的修订号。整实例迁移保留SQLite和附件，原用户资料不随代码推送。

生产模式设置 `SEDIMENT_ENV=production`、HTTPS `SEDIMENT_PUBLIC_URL` 和相同公开域名的 `SEDIMENT_MCP_PUBLIC_URL`，先离线执行 `scripts/provision-owner.py --email YOUR_EMAIL` 交互配置所有者。生产启动没有匿名所有者回退，也不允许第一个访客认领。公开运营还需反向代理、限流、邮件验证／找回与备份运维。本轮不部署，域名zhishi.51wanai.com留待用户后续通知。
